# 界面结构

每个窗口和视图为什么存在、分成哪几块，以及跳转的目的。增删视图或窗口时同步改这里（`TestIA` 对照清单）。

## 窗口

- **工作区窗口**：一个工作区一个窗口，再打开就聚焦已有的。标题栏左侧说明正在看什么：选中需求或分支时是需求号、需求名和增删行数，选中「未提交」时是它的名字，否则是工作区名；右侧是需求页的批量操作按钮，「创建 MR/PR」要处理的仓库数显示在按钮内的固定槽位里，不改变按钮宽度。只显示需求页，包含「未提交」入口；左栏宽度可调，底部是状态栏：最左端的按钮（⌘B）收起或展开左栏，最右端的按钮（⌥⌘B）收起或展开右栏的目录（窗口够宽且有文件时才有），收起状态随布局保存。设置在系统菜单栏「Sheaf › 设置…」里，或按 ⌘,，窗口里没有设置按钮。状态栏右侧是任务角：读取或更新数据、刷新远端、更新分支、创建 MR/PR、还原改动这些较长的动作是任务，持续 0.4 秒以上才出现，显示正在进行的任务名、进度条和「另有 N 个」；没有进行中的任务时，只剩一个历史图标（有未看过的失败时带红点），没有任何任务时整块隐藏。点击打开向上弹出的任务列表：进行中的在前，已结束的按时间倒序，每个任务列出各仓库的状态和结果，结束的标出多久前、用时和结果，有失败行的标「N 个失败」。创建 MR/PR 的行在创建或找到合并请求后显示「已创建 MR !12」这样的链接，点整行在浏览器里打开。刷新远端可立即停止；更新分支和创建 MR/PR 停止后，正在执行的那一行做完，其余标为「已停止」；更新数据和还原不能停止。顺利完成的数据更新不留在列表里，其余已结束任务保留到清除或关窗，最多 20 个。任务失败时提示框带「详情」按钮，打开任务列表；刷新远端顺利完成不再弹提示，更新分支和创建 MR/PR 确认后关闭确认窗，在后台运行。
- **改动窗口**：查看一个文件或提交的差异，固定在打开时的来源，支持并排和统一模式。外观与工作区窗口一致：标题栏写来源而不是某个文件（提交为短哈希加标题，未提交加目录名，需求为「需求 号 · 全部改动 / 待合 阶段 / 未提交」，全部改动附当前文件的比较范围），右侧是切换改动、切换文件和并排/单列，按钮位置固定，到头时置灰不可点，不隐藏；切换改动过了最后一处就到下一个文件，光标所在的改动用亮蓝边框标出（只有新增或只有删除行的文件不标）；只有新增或只有删除行的文件默认临时单列，在这个文件上改选并排只对它生效；左侧文件树用侧栏底色；底部状态栏放提交作者、时间和切换文件的快捷键。
- **设置窗口**：每个工作区一个，标题栏只显示「设置」。左栏上方是通用，下面按工作区分组列出我的提交、分支、仓库、MR/PR、数据；无工作区时只显示通用，可用 ↑↓ 切页，输入框保留编辑按键。右侧内容滚动，最大宽度 640，靠左排列。通用适用于所有工作区，我的提交、分支、仓库、MR/PR、数据 只管当前工作区。六页统一使用 18 号页标题、节标题与短说明，节之间以分隔线划分，设置项左侧名称与说明、右侧 240 宽控件。通用分语言、代码字体、命令行工具、关于四节，代码字体可从建议中选或输入任意已安装的等宽字体，没装时回落到内置的 Geist Mono；我的提交分邮箱和需求号写法，添加入口紧接邮箱列表；分支分合并流程、对比分支、各仓库主分支三节，当前终点分支并入流程说明，阶段添加入口为行内文字按钮；仓库页在包含的仓库节内先显示搜索与计数，再列出仓库；MR/PR 分 GitLab（glab）和 GitHub（gh）；数据页分提交数据和本地数据。流程阶段可编辑名称、目标分支、增删和排序，最后一个阶段为终点分支；新工作区默认只有 main 阶段，目标留空使用各仓库主分支，已有 master 设置用作阶段名和目标；显式保存过 release 的旧配置保留两阶段，已保存的自定义流程不变。流程同时用于左侧进度和「查看」里的各「待合」阶段，可只配置 origin/master。对比分支用于「全部改动」差异、↑↓ 和创建 MR/PR 的目标。通用页的关于节显示应用版本；操作记录按工作区记录，入口在数据页的本地数据节。仓库页支持按名称搜索，显示已包含数量，每行有加粗仓库名、包含状态和方形开关。改了即生效，工作区窗口随即跟上；保存失败恢复旧配置和表单值，并显示错误提示。

差异和设置随所属工作区窗口关闭。独立成窗是为了不打断主窗口的浏览上下文。

## 视图

### track

需求页（代码里仍叫筛选器页）：看一个需求在各仓库走到哪一步、给 master 带来什么改动，并在这里刷新远端、更新收藏分支和创建 MR/PR。这三个按钮在标题栏始终显示，不可用时置灰，悬浮提示说明原因（没选需求、各仓库都没有分支、分支都已合并）。

创建 MR/PR 先确认计划，再逐行执行；按 origin 的主机选择工具：github.com 用 gh 创建 PR，其余用 glab 创建 MR，不支持 GitHub Enterprise。确认窗和结果按行标出 MR 或 PR。更新分支和创建 MR/PR 的确认窗每行一条、不换行：仓库、分支走向（「feat → master」「release ← origin」）、几个字的动作或跳过原因，完整说明在悬浮提示里；缺少工具的行标「未安装 gh」并跳过，安装与登录命令在悬浮提示里，不阻塞其他可执行行。GitLab 的工作区登录配置只用于 glab，gh 使用自己的登录配置；设置窗口的 MR/PR 页分 GitLab（glab）和 GitHub（gh）两节：前者保留配置目录与登录命令，后者说明沿用系统 gh 登录，并提供可复制的 `gh auth login`；不提供 gh 配置目录或安装、登录状态。

切换需求时，上一个需求的页面保持不动、不可操作，新需求的概览、文件和行数统计都到齐后一帧内整页换上；超过 200 毫秒才变暗，不经过加载中或空白。

开发分支及其选择器只认包含完整需求号的本地或远程分支。找不到时按合并后已删除处理：进度显示已合并，提交历史保留，改动流和行数统计不包含该仓库。

左栏上面是查找框和固定的「未提交」入口，下面分上下两块，默认各占一半高度，中间的分隔线可拖动，各自滚动：上块是按阶段分组的关注中需求（已归档一组默认折叠成一行，查找有字或正在看其中一个时照常显示），下块是当前需求在各仓库的阶段，标题不随列表滚动，没选需求时显示提示；点击仓库定位到它在当前查看范围内的首个文件。切换需求不会挪动上块；需求行右键可重命名、归档、恢复或取消关注。查找框有字（或名单为空）时，关注中的需求下面是「可关注」小组：最多 8 个自动发现的候选和输入的需求号，点行临时看，点「关注」加入名单；回车先开第一个关注中的命中，再是把输入的完整需求号加入关注。名单为空时左栏提示输入需求号并直接列最近的候选；自动发现也没有候选时，主区解释需求号、分支名和本人提交标题的来源，显示当前写法，并提供直达设置「我的提交」页的按钮。查找框有字时多一行「搜索提交说明」，没有需求命中时回车也走这条路，是没有需求号的已提交修复的入口；结果作为唯一的临时条目显示，不保存。主区是「改动」「提交」两个页签，页签右侧是「查看」选择器（增删行数在标题栏），可切换「全部改动」「未提交」，以及合并流程每个阶段各一项「待合 阶段名」（名字取自配置，阶段多就列多项）；全部改动模式再选对比分支；空间不足时优先隐藏对比分支控件，保留「查看」选择器。需求打开后在后台数出每一项的文件数，没有文件的选项置灰、标「无改动」，不能选；当前所选的始终可选。切换只改变差异及其文件、行数统计，左侧阶段进度保持按合并流程判断；独立改动窗口沿用所选文件的比较范围。改动是按仓库分段、逐文件展开的差异流，仓库标题吸顶；文件标题左侧的箭头折叠或展开这个文件，只留标题，按住 ⌥ 点击或用标题菜单的「全部折叠」「全部展开」作用于全部文件，选择保留到文件离开列表；全部改动、待合阶段在各仓库的已提交文件之后列未提交文件，「未提交 · 位置 · 文件数」与仓库名共用同一条吸顶标题，不另起说明行，右栏目录仍按已提交与未提交分节。两种模式的「改动 N」和增删行数只计已提交部分；未提交模式只看关联目录的 HEAD 到工作区，标题同样显示未提交信息。未提交文件打开独立改动窗口时也看 HEAD 到工作区。提交页签是需求的提交列表。窗口够宽时右栏是差异流的目录，左边的分隔线可拖动调宽度。两处拖动的尺寸和左栏宽度一起存进工作区的布局，重开窗口仍然有效。

选中左栏「未提交」时，列出全部未提交目录，并标出归属的需求；入口计数包含全部脏目录。主区上下分栏：上方是目录列表，小标题显示目录数，右侧是仓库、工作目录和文件统计；下方有「文件 N」「改动 N」两个页签，文件列表和差异流按相同的仓库、工作目录、路径顺序组织。目录列表和文件列表都沿用差异流段标题的写法，不用带列头的表格：目录一行左侧是仓库、分支、归属需求号（若有），右侧是位置、文件数和最后改动，悬浮提示显示路径和可用的需求名；文件一行左侧是文件名和目录，右侧是仓库与位置、状态及增删行数，点击文件切到差异流并定位。文件行和差异流文件标题的右键菜单有「还原改动…」，新文件是「删除文件…」，确认后执行，不能撤销。点击目录同时限定下方两个页签，选中的目录用左栏同款的选中样式；再次点击同一目录、按 Esc 或点页签行右侧的取消按钮恢复全部。差异流每个工作目录一段，文件同样可用标题前的箭头折叠，标题提供仓库、分支、归属需求号（若有）、位置、文件数和最后改动。分隔线可拖动，高度只在这一页的生命期内保留；不再提供右栏文件跳转。只在目录变干净时自动取消限定，归属变化保留限定。没有未提交目录时，主区只显示「都已提交」。窄窗口下过长的内容截断，不横向滚动。

需求差异流的仓库标题在空间不足时截断项目名、工作目录名和分支名，保留未提交状态、文件数、阶段与领先/落后计数。未提交状态与文件数连在一起，随后显示位置；悬浮项目名、位置或分支可查看完整名称，位置还显示完整路径。

## 跳转

差异页签的顶栏仅在当前展示的改动发生变化时显示黄色「内容已变化 · 刷新」，读取期间显示「更新中」，失败时可重试；已是最新时不显示状态。工作区连续变化合并为同一条提醒，不闪烁、不弹通知。阅读期间保留现有差异，左栏的需求阶段和各仓库阶段照常更新（如刷新远端后发现已合并）；尚未加载的文件提示刷新后读取。切到提交或文件页签、其他需求，或窗口隐藏、最小化、完全遮挡后自动读取最新内容，回来继续看最新差异；窗口仍有可见部分时保留阅读内容，即使焦点在其他应用。

需求页不再提供日志跳转或文件历史入口；文件标题菜单可打开独立改动窗口、复制路径、全部折叠或全部展开。

| 从 | 到 | 目的 |
| --- | --- | --- |
| track | 改动窗口 | 查看选中提交的差异；冲突解决提交看相对重新合并结果的差异 |
| 需求页首次引导中的「修改写法」 | 设置窗口「我的提交」 | 调整需求号匹配写法 |
| 菜单栏「Sheaf › 设置…」或 ⌘, | 设置窗口 | 调整应用和当前工作区的设置 |
